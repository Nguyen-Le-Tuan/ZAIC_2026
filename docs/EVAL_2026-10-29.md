## 4. Sửa đường đánh giá ([PR #2](https://github.com/Nguyen-Le-Tuan/ZAIC_2026/pull/2))

- `train.py`:
  - Dev loss mặc định tính trên **mọi** dòng dev. `--eval-n > 0` lấy tập con ngẫu nhiên có seed, không lấy đầu file.
  - Ghi `run_info.json` gồm hash dữ liệu, hash và id của dev, commit và phiên bản thư viện.
  - Không ghi đè checkpoint đã có.
- `sft.py`:
  - Mỗi file SFT kèm `<file>.manifest.json` ghi id split, tham số, hash input và hash code.
  - `--reuse` chỉ giữ file cũ khi manifest khớp, hoặc khi dựng lại ra giống từng byte; nếu không thì dựng lại và cất file cũ sang tên khác.
- `infer.py`:
  - Ghi `<out>.meta.json` gồm id, model, sha256 của adapter, backend, seed, commit, phiên bản, latency p50/p95/max và lý do dừng.
  - Không ghi đè lượt chạy cũ.
- `agent.py`: trace lưu thêm kết quả tool mà model được thấy. Không đổi hành vi.
- Công cụ mới:
  - `lifemate.eval_loss`: loss trên toàn dev cho một checkpoint bất kỳ.
  - `lifemate.compare`: so sánh theo cặp, kèm bootstrap và lát cắt.
  - `scripts/eval_ckpt.sh`: đánh giá một checkpoint.
- `scripts/train_local.sh`:
  - Chọn được `FIT`/`DEV`, kiểm tra hai split không trùng mẫu.
  - Sau khi train, đánh giá rollout **mọi** checkpoint đã lưu rồi in bảng so sánh.
